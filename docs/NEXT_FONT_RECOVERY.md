## 已知事实与参考线索分开保存

用户报告证实：ID 647 (0x287) 指向 LBA 294280、91 个扇区，到镜像末尾 294371；目录没有对应路径。相邻 ID 646 指向 `AAA/DAT/COUNTRY/CMFONTCS.BIN`。目录还保留 `CMFONTTM.BIN`（LBA 2268，43660 字节）。

外部参考：`gascarcella/dw2003recomp/docs/FORMATS.md` 的 Font 段把 0x287 映射到 CMFONTTM（字形图像），0x286 为 CMFONTCS（窗口 sprite bank），字形度量位于 EXE。引用文档 blob：`da1d8d5d91c513e58ea9dd8e13681899b0119274`。这些只解释原版参考，不能证明汉化修改后的加载方式。

因此优先假设是：**647 可能被重定位到尾部的扩展字库**。这是待验证假设，不是坏档结论。尾部区域必须完整保留，严禁按 ISO 声明长度截断、作为空闲空间使用，或未经验证把 EXE 的 LBA 改回目录位置。

参考文档也描述 USA 的 USTALK08、USTALK09、USDMG900 为 512 个零字节。用户报告观察到相同现象；不主动“修复”为其他语言文本、不删除、不把它们虚算成已经翻译的条目。跨语言同名文件不能假定每条索引对应相同事件。

## 执行顺序及验收

### A. 固定输入和工作区

先 `git status`，保留用户现有改动；仅在工作区允许时执行 `git pull --ff-only`，不要 reset、强推或删除私有文件。记录实际执行的 commit 与工作树状态；现有报告未提供准确扫描代码 commit，不得从报告日期推定。

找到此前 probe 目录内的两份分享报告和私有索引，复用现有成果。原 ZIP/镜像保持只读，以精确哈希确认输入；不得下载别的 ROM 替代。分析输出放到 Git 忽略的 `local/font-recovery/`。

### B. 确认选择「中文」后的实际资源路径

通过用户镜像中的语言选择代码/状态、文本加载调用或模拟器跟踪，确定选择中文时的 language 值以及对话、菜单实际加载的文件 ID。不因目录写着 ENG 就认定所有中文一定来自 ENG。

为至少一条已知中文对白建立来源链：语言选择状态 → 文件 ID/LBA → 子表与条目 → 字节 → 解码/绘字函数。动态人名、菜单小字等可能走不同路径，分别登记。没有证据的路径标记 unresolved。

### C. 只读分析 ID 647，并证明字库来自哪里

按 **EXE 文件表的 LBA/扇区数**读取 647 的 91 个物理扇区，不仅按 ISO 文件路径读取。分别记录原始 2352 扇区区块与逐扇区 2048 用户数据的哈希，逐扇区检查同步头、模式、重复子头、Form 类型和 EDC/ECC；遇到不支持的格式停止解析，不先改写校验码。

比较尾部资源与目录中的 CMFONTTM，检查容器/压缩/图像结构，所有长度和指针必须有边界检查。参考 TIM/RLEN 仅是候选，不能在未验证时强行按该结构解释。跟踪加载 0x287 的调用及目标内存/显存；可能需要分析改过的 EXE 或 overlay，而非只相信原版函数地址。

本地保存字形图像/图集用于人工核查，记录它们的资源来源、图块或 glyph 索引、尺寸及编码关联。不要把字体文件、完整字库、游戏纹理或原始二进制提交到公开仓库。

### D. 恢复原汉化编码与实际渲染度量

以实际修改后的解码/绘制代码为准，确认字节分段、前导字节、终止符、控制码及参数。不要直接按 GBK、UTF-8 或 Shift-JIS 强制解码；也不要把旧对话中“1997 个字形”当作已证实的数量。

核对当前工具中对 0x01/0x02/0x03、固定控制长度、首次 NUL 截止的假设。`prepare_translation_patch.py` 和 `apply_text_bytes.py` 的分词边界必须对同一真实字符串一致；发现冲突先统一解析器，不能绕过检查。控制参数、字形多字节中的零值如何解释，要依据实际代码，而非简单禁止或截断。

为每个已确认的汉字记录：Unicode、字节序列、glyph 索引/来源、对应字号、advance/offset/实际墨迹边界、确认依据。OCR 或视觉匹配仅能给候选，不得自动成为 reviewed 映射；未确认字符留作 unresolved，不能猜字。

优先恢复第一组待补翻所需字符及可用于交叉检查的已有中文。不要为追求“全部恢复”而先伪造一张完整码表。

### E. 无损回环和候选分级

使用确认后的解析器对已确认的中文路径做 原始字节 → token 序列 → 原始字节 回环。逐条保留编码、控制参数、终止符及字节哈希；至少覆盖当前已确认相关资源中的全部可解析条目，并报告总数、unknown 数、失败数及各类原因。

**原样保留未知 token 使回环通过，不等于成功解码了中文。** 分别报告 token-lossless 率、已识别字形/Unicode 覆盖率和实际画面核验范围。文件级无改动重建还应保留头部、指针、对齐、填充与未使用区域。

建立私有候选表，区分：已确认漏译、专有名称/允许缩写、已中文、图像文字、未知编码。英文模式命中只是候选。对卡牌图鉴/商店或指南中一条可稳定触发的短文本，记录实际文件 ID、条目、原文/控制码、容量和窗口，而不是沿用草案中的猜测位置。

### F. 条件满足后只做一个真实补翻样板

只有 B–E 对该样板所需路径和全部字符均有充分证据，才生成全新镜像，不覆盖原件。沿用既有术语，译文等长/缩短必须同时满足字节容量和像素宽度/墨迹边界，不能用错误缩句迁就工具；不满足就停止并记录扩容需求。

验证所有未修改文本、指针和镜像区块不变；包含 ID647 的尾部资源必须原样保留。改动扇区要验证 EDC/ECC；校验失败不静默修复。保存修改范围、输入/输出哈希、局部差异补丁与回退说明。

模拟器可用时，以用户提供的合法 BIOS/镜像和正常存档验证：启动、目标画面、选项返回、相关功能、真正存读档。记录模拟器版本/配置、触发步骤及前后截图。没有模拟器或所需进度存档时，提供精确人工测试步骤并标记 runtime_pending，不将工具测试写成游戏内通过。
