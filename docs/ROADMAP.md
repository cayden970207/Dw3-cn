# 分阶段交付与验收

每阶段保存：输入指纹、变更清单、检查日志、可复现操作、已知问题。翻译草稿、写回成功、静态检查通过、游戏内验证分别计数。

| 阶段 | 范围 | 出口条件 |
|---|---|---|
| P0 恢复基线 | 镜像指纹、原汉化来源、字库、文本结构与回写工具 | 无改动回写字节对齐；已有汉化开场可重现；可回退 |
| P1 系统补翻 | 卡牌、指南、进化、训练、商店、战斗、道具与技能提示、存读档 | 已知系统文本逐条对齐；所有相关窗口按实际字宽检查；实际操作通过 |
| P2 剧情 | 主线、支线、NPC、隐藏事件、结局、欧版通关后内容 | 全流程检查表逐项有证据；没有未解释的漏译 |
| P3 术语与图像文字 | 人物、数码兽、招式、地图、UI 图像内文字 | 与已有汉化统一；逐屏比对；缩写白名单可审计 |
| P4 回归 | 小字号、最长名称、动态值、分页、所有分支、战斗、卡牌、存读档 | 静态及运行检查通过；已知文字/显示问题清零；未覆盖项不隐藏 |
| P5 发布 | 增量补丁、精确哈希、署名、使用说明与回退 | 从干净基线重建并重新应用成功；与发布哈希一致；记录适用平台 |

## 重点风险

- 使用实际中文字库的字宽和绘制边界，不能按汉字数量估算。
- 所有字号、特殊窗口、图像内文字都要核查，普通对白成功不代表菜单成功。
- 插入的人名、道具名、技能名、数字和计数必须测试边界值；不要将示例中的 48 px 当作游戏事实。
- 不自动删除未知控制码，不截断超长译文，不靠缩小字体掩盖排版错误。
- 等待、选项、跳转、分页、说话人和动态插入的语义必须保留。
- 实际重打包还要检查指针、对齐、资源容量、压缩及必要的 CD 校验；当前静态工具不处理这些。

## 运行证据最低内容

精确基线与补丁 SHA-256、工具 commit、模拟器和版本、配置、普通存档/可复现输入、触发路径、修改前后截图、预期与实际结果。读写存档必须真实执行，不能只打开读档菜单。

最终目标是全覆盖、无已知汉化文字和显示缺陷；绝对零 Bug 不作为未经验证的承诺。
