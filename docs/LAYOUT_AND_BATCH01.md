# 中文排版、未知 token 与卡牌菜单批次

## 区分三种量

本轮只对精确镜像 `c7130c53…77fc` 的 **font 1、palette 0、非缩放、比例字宽、存储文本**建立离线模型。`tools/layout_cn.py` 从实际 EXE 读 glyph 度量，从 ID 647 的真实纹理和对应 CLUT 计算非透明墨迹；它分开报告：

1. 实际绘制时的逐行推进和像素边界；
2. 按实际 EXE 旧测宽逻辑静态模拟的返回值；
3. 调用窗口是否真的使用测宽结果，以及它在画面中允许的范围。

旧测宽的数字不是对游戏函数的现场调用。图鉴标题窗口 `(16,25)` 没调用测宽；实际中文推进 48 像素、旧测宽静态结果 22 像素。原文与中文标题的预测墨迹边界均与模拟器截图像素边界一致。图鉴右上标签的原点为 `(208,25)`，真实墨迹右端为 x=300，距离 320 像素屏幕右边界 20 像素；精确窗口裁切边界仍未知。

卡片商店主菜单三行使用 font 1，原点 `(167,53)`、`(167,67)`、`(167,81)`；无卡包提示为 `(154,113)`；卡组子菜单第一行为 `(167,35)`。真实汉化镜像中的 `STCRDABM.PRO`、`STCRDSHP.PRO`、`STCRDDEK.PRO` 分别与固定参考 overlay 的 SHA-1 一致，结合对应源码与实际画面确认这些目标窗口不调用通用测宽。实际屏幕的硬边界不是普遍适用的窗口宽度；批次写入还要求目标墨迹落在已观察的原文字带内，并在运行截图上重新验证。

真实源条目的纯中文、中英混排、数字、标点/空格、显式换行和具体数值插入均在 `reports/SHARE_THIS_layout_validation_report.json` 中有独立结果。另通过独立存档与自然输入进入数码兽研究所的进化表，确认 resource 59 / entry 39 用控制码 5 插入当次数码兽名称：实际 font 1、palette 0、未缩放，推进 72 像素，预测与画面墨迹边界均为 `[20,25,91,36)`。同一次静态模拟旧测宽为 44 像素；运行窗口本身的 `measured_width` 为 0，源码显示该标题并未调用旧测宽。私有名称、存档及截图保留在本地。这个动态名称结果只针对该次内容；插入值 10000 也只是一个静态情景，都不是动态数据的上界。

未列为画面验证的样本仍是静态测量；其他 font、palette、缩放、居中、换页、其他动态名称及未支持控制码均不能据此放行。通用 `apply_text_bytes.py` 对该镜像继续拒绝写入，本轮没有修改游戏测宽代码，也没有解除封锁。

## 已确认与未确认的字形

26 个独立字形及标准码记在 `data/baselines/c7130c53-reviewed-glyphs.json`；第一批相关预览增加「打、开、回、有、包、买、一、张、编、辑、组、没」12 个，后续又由用户确认「称、金、不、足、钱」5 个。索引中 9,728 次 token 属于这 26 个字形，其余 102,893 次仍未确认身份。OCR 和字体模板仅用于产生候选，不成为 reviewed；例如 glyph 523、756、164、1489、1151 仍未确认，不得用来写入。

## 旧样板回归

`tools/album_regression.py` 从先前自动生成的私有存档复制出独立记忆卡，不写源卡；用样板 CUE 在新进程读档、走到图鉴，通过实际游戏对象页码观察 1→2→1→27→1，并用截图检查首页、次页、末页和返回首页。再次打开退出后进入卡组并回到场景，走回旅馆，用游戏界面覆盖**独立副本**的存档。代码等待新的写入状态及完成计数，退出第一个模拟器进程，再把该卡复制到第二个新进程冷启动，通过游戏内读档验证卡片盒物品并重开图鉴。没有使用内存注入或依赖旧的完成标志。早期失败尝试和日志保留在 ignored `local/`，不计为通过。

`tools/collect_album_regression.py` 将页码、检查点、模拟器/BIOS 版本、警告数和截图哈希汇总为脱敏报告。`Unknown command for pad: 43` 在启动时仍有日志，但已观察到上述实际页面、保存、读取和菜单状态的转换，故这些特定动作成功；不能据此判断所有手柄命令。

## 批次构建与运行

`data/p1_batch01_reviewed.json` 列出前一处图鉴标题及五个新增条目的原文哈希、中文译文和角色。`tools/make_card_menu_batch.py` 必须从精确原始 ZIP 重建，校验三个菜单 overlay、真实索引、用户审阅映射、逐项控制码和容量、原画面像素及目标墨迹；它只接受固定的六个条目。对复制出的全新镜像，脚本对两个变更扇区重算并验证 EDC/ECC，然后逐字节比较整个原始镜像，确认所有差异位于六个文字区或相应校验字节、ID 647 完全不变。每个批次目录必须不存在；输出不可覆盖。局部差异及游戏资源只留本地。

`tools/replay_card_shop.py` 使用冷读后的独立卡片盒存档副本，分别重放商店及卡组子菜单；另一次进入图鉴确认旧标题。`tools/collect_card_batch.py` 检查实际游戏状态、屏幕区域前后差异和每条目标的预测/截图墨迹边界，需人工目视后才可使用 `--visual-checked`。该参数只记录已完成的人眼审阅，不能用来伪造结果。实际五条新译文已各自出现在画面，比较中对应区域外的同帧截图像素一致。

后续以 `tools/batch01_save_regression.py` 和独立记忆卡运行批次回归：先访问图鉴、卡组、商店及无卡包提示，观察写卡开始、结束和保存画面；完全退出后用第二个进程冷启动、从游戏内读档，验证卡片盒并重访这些菜单。`tools/collect_batch01_save_regression.py` 核查实际对象状态、检查点顺序，以及文字区域与前次已审核截图的像素掩码；结果见 `reports/SHARE_THIS_p1_batch01_save_regression_report.json`。

批次截图与镜像位于本机 `local/font-recovery/p1-batch01*/`，单标题对照继续保留在 `local/font-recovery/run-20261107/card_album_test/`。`reports/SHARE_THIS_p1_batch01_report.json` 包含十条候选的资源 ID、条目、原文哈希、调用窗口及触发条件，其中 5 条已写入并运行验证、5 条仍未修改。截图及存档不提交 GitHub。

第二批后续新增 52/19「金钱不足」：源文字推进 93 像素、译文推进 48 像素；译文在实际不足余额提示窗口的墨迹边界为 `[154,57,200,68)`，与预测吻合，旧测宽的静态结果为 20 像素且该窗口不调用它。该副本已独立访问提示、保存、冷启动读档并再次显示提示；详情见 `docs/BATCH02.md` 和第二批两份报告。第一批报告中的候选状态为当时的历史快照。

## 未知 token 的调用上下文

`tools/unknown_token_audit.py` 对六处重新核对原资源和实际 overlay：ID 199/77、78 对应 WSTAG200 的 actor 178；ID 206/368 对应 WSTAG520 的 actor 103；ID 213/765 对应 WSTAG620 的 actor 101；ID 220/513、520 分别对应 WSTAG226 的 actor 104、178。各 overlay 与固定上游 SHA-1 相符，实际镜像中的对白表索引和 actor 指针也通过检查；条件标志和实际触发仍未验证。五次扩展 token 超出已检查 font 1 的表界，一次为 fallback；两者都保留原样，不自动判断为损坏。报告只写位置、入口和长文本哈希，不公开原字节或短 token 的可逆哈希。
